## 1. 当前项目的 LLM 调用方式

### 1.1 核心代码分析

项目的 API 客户端初始化集中在 `bootstrap/state.py`：

```python
# bootstrap/state.py
import os
from anthropic import Anthropic

# 加载 .env 环境变量
load_dotenv(override=True)

# 自定义 base_url 时移除可能冲突的 auth token
if os.getenv("ANTHROPIC_BASE_URL"):
    os.environ.pop("ANTHROPIC_AUTH_TOKEN", None)

# API 客户端与模型
client = Anthropic(base_url=os.getenv("ANTHROPIC_BASE_URL"))
MODEL = os.environ["MODEL_ID"]
```

核心调用在 `query.py` 的 `agent_loop` 函数中：

```python
# query.py — 主循环中的 LLM 调用
response = client.messages.create(
    model=MODEL,
    system=system_prompt,       # str 或 list[dict]（带 cache_control）
    messages=messages,          # 对话历史
    tools=tool_defs,            # 工具定义列表
    max_tokens=8000,
)
```

除了主循环，项目中还有三个地方调用 LLM：

| 调用位置 | 文件 | 用途 |
|---------|------|------|
| 主 Agent 循环 | `query.py` L104 | 核心对话循环 |
| SubAgent 执行 | `agents/subagent.py` L33 | Worker Agent 的独立循环 |
| Teammate 循环 | `agents/team.py` L208 | 多 Agent 协作中的独立循环 |
| 压缩摘要 | `services/compact.py` L368 | AutoCompact 摘要生成 |

**关键发现**：所有调用点使用同一个 `client` 实例和同一个 `MODEL`。这意味着切换模型是全局性的——要么全部切，要么全部不切。

### 1.2 参数格式详解

每次 API 调用传递的参数：

```python
{
    "model": "claude-sonnet-4-20250514",   # 模型 ID（字符串）
    "system": [                              # 系统提示（字符串或 block 数组）
        {
            "type": "text",
            "text": "You are a coding agent...",
            "cache_control": {"type": "ephemeral"}   # Prompt Cache 标记
        },
        {
            "type": "text",
            "text": "# Environment\nOS: ..."         # 动态部分，无缓存
        }
    ],
    "messages": [                             # 对话历史
        {"role": "user", "content": "帮我写一个函数"},
        {"role": "assistant", "content": [...]},
        {"role": "user", "content": [...]},
    ],
    "tools": [                                # 工具定义
        {
            "name": "bash",
            "description": "Execute a bash command...",
            "input_schema": {                 # 注意：是 input_schema，不是 parameters
                "type": "object",
                "properties": {
                    "command": {"type": "string", "description": "..."},
                },
                "required": ["command"]
            }
        },
        # ... 更多工具
    ],
    "max_tokens": 8000                        # 最大输出 token 数
}
```

### 1.3 响应格式

Anthropic API 的响应结构：

```python
# response 对象的关键字段
response.content          # list[ContentBlock] — 模型输出
response.stop_reason      # "end_turn" | "tool_use" | "max_tokens"
response.usage.input_tokens
response.usage.output_tokens
response.usage.cache_creation_input_tokens   # Prompt Cache 写入
response.usage.cache_read_input_tokens       # Prompt Cache 命中

# content 中可能包含的 block 类型
# 1. 文本块
{"type": "text", "text": "让我来看看这个文件..."}

# 2. 工具调用块
{
    "type": "tool_use",
    "id": "toolu_01ABC...",
    "name": "bash",
    "input": {"command": "ls -la"}
}
```

项目中对响应的处理：

```python
# query.py — 响应处理
messages.append({"role": "assistant", "content": response.content})
tracker.update_from_response(response)

if response.stop_reason != "tool_use":
    return tracker, breaker

# 如果有工具调用，执行工具并把结果追加到 messages
for block in response.content:
    if block.type == "tool_use":
        # 执行工具，获取结果
        output = tool_handlers[block.name](block.input)
        results.append({
            "type": "tool_result",
            "tool_use_id": block.id,
            "content": output,
        })
messages.append({"role": "user", "content": results})
```

### 1.4 环境变量配置

```bash
# .env 文件中与模型相关的配置
ANTHROPIC_API_KEY=sk-ant-xxxxx           # API 密钥（SDK 自动读取）
ANTHROPIC_BASE_URL=                       # 可选，覆盖 API 端点
MODEL_ID=claude-sonnet-4-20250514       # 模型 ID
MODEL_CONTEXT_WINDOW=200000              # 上下文窗口大小（影响压缩策略）
```

## 2. Anthropic API 格式深度剖析

要理解"能否只改 base_url 切换模型"，必须先搞清楚 Anthropic API 与 OpenAI API 的格式差异。

### 2.1 Anthropic vs OpenAI API 格式对比

| 特性 | Anthropic API | OpenAI API |
|------|-------------|------------|
| **System Prompt** | 独立的 `system` 参数 | `messages[0]` 中 `role: "system"` |
| **System 格式** | `str` 或 `list[dict]`（支持 cache_control） | 仅字符串 |
| **工具定义字段** | `input_schema` | `parameters`（在 `function` 内） |
| **工具定义结构** | 扁平：`{name, description, input_schema}` | 嵌套：`{type: "function", function: {name, description, parameters}}` |
| **工具调用响应** | `content` 中的 `tool_use` block | `tool_calls` 数组 |
| **工具调用 ID** | `tool_use_id` | `tool_call_id` |
| **工具结果** | `tool_result` block 在 user message 的 content 中 | `role: "tool"` 的独立 message |
| **停止原因** | `stop_reason: "tool_use"` | `finish_reason: "tool_calls"` |
| **缓存控制** | `cache_control: {type: "ephemeral"}` | 无对应字段（自动前缀缓存） |
| **Token 用量** | `usage.cache_creation_input_tokens` 等 | `usage.prompt_tokens` 等 |

### 2.2 具体格式差异示例

**Anthropic 格式的工具调用请求：**

```json
{
    "model": "claude-sonnet-4-20250514",
    "system": "You are a helpful assistant.",
    "messages": [
        {"role": "user", "content": "今天天气怎么样？"}
    ],
    "tools": [
        {
            "name": "get_weather",
            "description": "获取天气信息",
            "input_schema": {
                "type": "object",
                "properties": {
                    "city": {"type": "string"}
                },
                "required": ["city"]
            }
        }
    ],
    "max_tokens": 1024
}
```

**OpenAI 格式的等价请求：**

```json
{
    "model": "gpt-4o",
    "messages": [
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "今天天气怎么样？"}
    ],
    "tools": [
        {
            "type": "function",
            "function": {
                "name": "get_weather",
                "description": "获取天气信息",
                "parameters": {
                    "type": "object",
                    "properties": {
                        "city": {"type": "string"}
                    },
                    "required": ["city"]
                }
            }
        }
    ],
    "max_tokens": 1024
}
```

**Anthropic 格式的工具调用响应：**

```json
{
    "content": [
        {"type": "text", "text": "让我查询一下北京的天气。"},
        {
            "type": "tool_use",
            "id": "toolu_01ABC",
            "name": "get_weather",
            "input": {"city": "北京"}
        }
    ],
    "stop_reason": "tool_use"
}
```

**OpenAI 格式的等价响应：**

```json
{
    "choices": [
        {
            "message": {
                "role": "assistant",
                "content": "让我查询一下北京的天气。",
                "tool_calls": [
                    {
                        "id": "call_abc123",
                        "type": "function",
                        "function": {
                            "name": "get_weather",
                            "arguments": "{\"city\": \"北京\"}"
                        }
                    }
                ]
            },
            "finish_reason": "tool_calls"
        }
    ]
}
```

### 2.3 为什么格式差异很重要

当前项目**深度绑定了 Anthropic API 格式**。以下是项目中依赖 Anthropic 格式的关键位置：

1. **`query.py`**：`response.stop_reason == "tool_use"` 判断是否需要执行工具
2. **`query.py`**：`block.type == "tool_use"` 遍历工具调用
3. **`query.py`**：`block.id` 作为 `tool_use_id` 返回结果
4. **`context.py`**：`cache_control` 字段用于 Prompt Cache
5. **`services/compact.py`**：`response.usage.cache_read_input_tokens` 追踪缓存效果
6. **所有调用点**：`system` 作为独立参数传递

**结论**：如果要用 OpenAI 格式的 API（如 DeepSeek 官方 API），需要改动至少 4 个文件中的响应处理逻辑。但如果通过兼容 Anthropic 格式的代理转发，则**零改动**。

## 3. 是否只改 base_url 就能切换 LLM？

### 3.1 结论先行

**可以，但有前提条件。**

```
能否只改 base_url 切换？
        │
        ├── 代理支持 Anthropic API 格式？
        │      │
        │      ├── 是 → 只改 base_url + API_KEY + MODEL_ID 即可
        │      │          例：OpenRouter（Anthropic 兼容模式）
        │      │
        │      └── 否 → 需要格式转换层
        │                例：大部分国内代理只支持 OpenAI 格式
        │
        └── 直连模型官方 API？
               │
               ├── Anthropic 格式 → 只改 base_url 即可
               │    （但目前只有 Anthropic 自己用这个格式）
               │
               └── OpenAI 格式 → 需要改代码或加适配层
                    例：DeepSeek、Qwen、GPT 官方 API
```

### 3.2 直接切换可行的情况

以下代理/网关兼容 Anthropic API 格式，可以直接切换：

| 代理服务 | 兼容 Anthropic 格式 | 支持的模型 | base_url |
|---------|:---:|---------|---------|
| OpenRouter | 是 | 100+（GPT/Claude/DeepSeek/Qwen/Gemini 等） | `https://openrouter.ai/api/v1` |
| Amazon Bedrock | 是 | Claude 全系列 | 区域端点 |
| Google Vertex AI | 是 | Claude 全系列 | 区域端点 |

**OpenRouter 是唯一同时支持 Anthropic 格式 + 多模型 的公共代理。**

具体配置：

```bash
# .env — 通过 OpenRouter 使用 DeepSeek
ANTHROPIC_BASE_URL=https://openrouter.ai/api/v1
ANTHROPIC_API_KEY=sk-or-v1-xxxxx
MODEL_ID=deepseek/deepseek-chat
MODEL_CONTEXT_WINDOW=64000
```

### 3.3 不能直接切换的情况

以下代理/API 只支持 OpenAI 格式，**不能**只改 base_url：

| 服务 | API 格式 | 能否直接切 | 备注 |
|------|---------|:---:|------|
| DeepSeek 官方 API | OpenAI | 否 | 需要适配层 |
| 阿里云通义千问 API | OpenAI | 否 | 需要适配层 |
| 智谱 GLM API | OpenAI | 否 | 需要适配层 |
| SiliconFlow（硅基流动）| OpenAI | 否 | 需要适配层 |
| 大部分国内代理 | OpenAI | 否 | 需要适配层 |
| OneAPI（自建） | OpenAI | 否 | 除非配置了 Anthropic 转换 |

### 3.4 关于 OpenRouter 的 Anthropic 兼容性

OpenRouter 同时提供两种 API 格式入口：

- **OpenAI 兼容端点**：`https://openrouter.ai/api/v1`（默认，用 `openai` SDK）
- **Anthropic 兼容端点**：`https://openrouter.ai/api/v1`（用 `anthropic` SDK 时自动识别）

当你用 `anthropic` SDK 的 `client.messages.create()` 方法调用 OpenRouter 时，OpenRouter 会：

1. 接收 Anthropic 格式的请求（system 参数、input_schema、tool_use 等）
2. 内部转换为目标模型的原生格式
3. 调用目标模型
4. 将响应转换回 Anthropic 格式返回

**这意味着 tool calling 的 `input_schema`/`tool_use`/`stop_reason` 等字段都会被正确处理。**

但需要注意：
- `cache_control` 字段在非 Claude 模型上会被忽略（不报错，但无效果）
- 某些模型的 tool calling 能力较弱，可能无法正确处理复杂工具调用
- 响应中的 `usage` 字段格式可能略有差异

### 3.5 实际验证方法

切换前建议做如下验证：

```python
# 验证脚本 — 测试新 base_url 是否兼容
import os
os.environ["ANTHROPIC_BASE_URL"] = "https://openrouter.ai/api/v1"
os.environ["ANTHROPIC_API_KEY"] = "sk-or-v1-xxxxx"

from anthropic import Anthropic
client = Anthropic(base_url=os.environ["ANTHROPIC_BASE_URL"])

# 测试 1: 基本对话
resp = client.messages.create(
    model="deepseek/deepseek-chat",
    system="You are a helpful assistant.",
    messages=[{"role": "user", "content": "Hello"}],
    max_tokens=100,
)
print("基本对话:", resp.content[0].text)
print("stop_reason:", resp.stop_reason)

# 测试 2: 工具调用
resp = client.messages.create(
    model="deepseek/deepseek-chat",
    system="You are a coding assistant. Use tools when needed.",
    messages=[{"role": "user", "content": "请读取 README.md 文件"}],
    tools=[{
        "name": "read_file",
        "description": "Read a file",
        "input_schema": {
            "type": "object",
            "properties": {"path": {"type": "string"}},
            "required": ["path"]
        }
    }],
    max_tokens=500,
)
print("工具调用:", resp.stop_reason)
for block in resp.content:
    print(f"  block type: {block.type}")
    if block.type == "tool_use":
        print(f"  tool: {block.name}, input: {block.input}")
```

## 4. API 代理网关调研

### 4.1 OpenRouter（推荐首选）

**官网**：https://openrouter.ai

**核心优势**：
- 统一入口访问 100+ 模型（截至 2026 年初）
- 同时兼容 OpenAI 和 Anthropic API 格式
- 自动故障转移（某个提供商挂了自动切到备用）
- 用量统计和成本追踪面板

**支持的主要模型**：

| Claude Haiku 4.5 | `anthropic/claude-haiku-4-5` | $0.80 | $4.00 |
| GPT-4o | `openai/gpt-4o` | $2.50 | $10.00 |

**注册与使用**：

**配置示例**：


**注意事项**：
- OpenRouter 在原模型价格基础上加 ~5% 手续费
- 免费模型（如部分 Llama）在 OpenRouter 上也是免费的
- 有速率限制，免费用户更严格
- 中国大陆访问可能需要网络工具

### 4.2 SiliconFlow（硅基流动）— 国内推荐

**官网**：https://siliconflow.cn

**核心优势**：
- 国内服务，访问稳定，无需科学上网
- 价格低，部分模型免费
- 支持 DeepSeek、Qwen、GLM 等国产模型

**重要限制**：
- **只支持 OpenAI API 格式**，不兼容 Anthropic 格式
- 不能直接用 `anthropic` SDK 调用
- 需要适配层（见第 9 节）或通过 litellm 中转

**支持的模型**：

| GLM-4-9B | `THUDM/glm-4-9b-chat` | 免费 | 免费 |

### 4.3 OneAPI / New API（自建网关）

**项目地址**：
- OneAPI: https://github.com/songquanpeng/one-api
- New API: https://github.com/Calcium-Ion/new-api（OneAPI 的增强分支）

**核心优势**：
- 完全自主可控

- 可以将 OpenAI 格式转为 Anthropic 格式（需要配置）

**局限**：
- 需要自己部署和维护服务器
- 默认只支持 OpenAI 格式转发
- Anthropic 格式兼容需要额外配置或二次开发

**部署方式**：


## 5. 主流 LLM 模型对比

### 5.1 编码能力排行（2026 年初）

| 2 | Claude Sonnet 4 | Anthropic | ~70 | 极强 | 200K |
| 3 | GPT-4o | OpenAI | ~65 | 强 | 128K |
| 4 | DeepSeek V3 | DeepSeek | ~60 | 强 | 64K |
| 5 | Gemini 2.0 Pro | Google | ~58 | 中等 | 1M |
| 6 | Qwen 2.5 Max | 阿里云 | ~55 | 中等 | 128K |
| 7 | DeepSeek R1 | DeepSeek | ~53 | 中等 | 64K |

## 7. Tool Calling 兼容性深度分析

### 7.1 为什么 Tool Calling 是关键

当前项目注册了大量工具：

| 工具 | 文件 | 功能 |
|------|------|------|
| bash | `tools/BashTool.py` | 执行 shell 命令 |
| read_file | `tools/FileReadTool.py` | 读取文件 |
| edit_file | `tools/FileEditTool.py` | 编辑文件（精确替换） |
| write_file | `tools/FileWriteTool.py` | 写入文件 |
| grep_search | `tools/GrepSearchTool.py` | 搜索文件内容 |
| list_files | `tools/ListFilesTool.py` | 列出文件 |
| agent | `tools/AgentTool.py` | 派生子 Agent |
| todo | `tools/TodoTool.py` | 任务管理 |
| task | `tools/TaskTool.py` | 后台任务 |
| skill | `tools/SkillTool.py` | 技能调用 |

Agent 的核心循环是：**LLM 决策 → 工具调用 → 工具执行 → 结果返回 → LLM 再决策**。如果模型的 tool calling 不准确，整个流程就会断裂。

### 7.2 常见的 Tool Calling 问题

在非 Claude 模型上，可能遇到的问题：

**问题 1：参数类型错误**

```python
# 正确：path 应该是字符串
{"name": "read_file", "input": {"path": "/src/main.py"}}

# 错误：某些弱模型可能生成
{"name": "read_file", "input": {"path": 123}}        # 数字类型
{"name": "read_file", "input": {"file": "/src/main.py"}}  # 错误的参数名
```

**问题 2：多工具调用失败**

Claude 能在单次响应中调用多个工具：

```python
# Claude 的响应可能包含多个 tool_use block
response.content = [
    {"type": "text", "text": "让我先搜索再读取文件"},
    {"type": "tool_use", "id": "t1", "name": "grep_search", "input": {...}},
    {"type": "tool_use", "id": "t2", "name": "read_file", "input": {...}},
]
```

某些模型（尤其是较小的开源模型）在并行调用多个工具时容易出错。

**问题 3：工具不被调用**

某些模型倾向于直接回答，而不是使用工具：

```
用户：请读取 main.py 的内容
模型（期望）：调用 read_file 工具
模型（实际）：main.py 的内容大概是...（胡编乱造）
```

**问题 4：JSON 格式错误**

```python
# 正确
{"command": "ls -la"}

# 错误：某些模型可能输出
{"command": "ls -la",}          # 尾逗号
{'command': 'ls -la'}           # 单引号
{command: "ls -la"}             # 无引号 key
```

**1. 简化工具定义**

## 8. Prompt Cache 在其他模型上的表现

### 8.1 当前项目的 Prompt Cache 实现

项目在 `context.py` 中将系统提示分为静态和动态两部分：

```python
# context.py — build_system_prompt() 返回的格式
[
    {
        "type": "text",
        "text": "You are a coding agent...(规则、工具指引等不变的内容)",
        "cache_control": {"type": "ephemeral"}   # ← 告诉 API 缓存这部分
    },
    {
        "type": "text",
        "text": "# Environment\nOS: Windows...(动态内容)"
        # 无 cache_control → 不缓存
    }
]
```

这是 Anthropic API 的专有功能。在 Claude 模型上，缓存命中时输入 token 的价格降低到 **1/10**，效果显著。

### 8.2 各模型/平台的缓存支持情况

| 模型/API | Prompt Cache | 机制 | 对 cache_control 的处理 |
|---------|:---:|------|------|
| Claude（Anthropic 直连） | 有 | 显式标记 `cache_control` | 原生支持，90% 成本优化 |
| Claude（OpenRouter 转发） | 可能有 | 取决于 OpenRouter 是否透传 | 可能有效，但不保证 |
| GPT-4o（OpenAI） | 有（不同机制） | **自动前缀缓存**，无需标记 | 字段被忽略，OpenAI 自动缓存相同前缀 |
| DeepSeek V3 | 有（Context Caching） | 类似 OpenAI 的自动缓存 | `cache_control` 字段被忽略 |
| Qwen | 无 | — | 字段被忽略 |
| GLM | 无 | — | 字段被忽略 |
| Gemini | 有（Context Caching） | 需要单独 API 调用创建缓存 | `cache_control` 字段被忽略 |

### 8.3 切换模型后的缓存影响

```
切换到非 Claude 模型后：
├── cache_control 字段 → API 忽略（不会报错）
├── 缓存效果 → 丧失（除非目标模型有自己的缓存机制）
├── 功能影响 → 无（只是每次全量计费）
└── 成本影响 → 增加（但如果模型本身便宜，总成本可能仍然更低）
```

**实际影响估算**：

假设 100 轮对话，系统提示约 5K tokens：

| 方案 | 有缓存 | 无缓存 | 差额 |
|------|---:|---:|---:|
| Claude Sonnet 4 | $2.50 | $4.00 | +$1.50 |
| DeepSeek V3 | — | $0.40 | — |

即使 DeepSeek V3 没有缓存优惠，总成本仍远低于有缓存的 Claude Sonnet。

### 8.4 结论

**Prompt Cache 是锦上添花，不是核心功能。** 切换到便宜模型后，即使失去缓存，总成本仍然更低。代码中的 `cache_control` 字段不需要删除——它在非 Claude 模型上会被静默忽略。

## 9. 适配多 LLM 的工程方案

如果不想依赖 OpenRouter，而是直接调用各模型的官方 API，有以下方案：

### 9.1 方案 A：LLMClient 抽象层（手动实现）

在项目中新建一个 `llm_client.py`，封装不同 API 格式的差异：

```python
# llm_client.py — LLM 客户端抽象层（约 150 行）
import os
import json
from abc import ABC, abstractmethod


class LLMClient(ABC):
    """LLM 客户端抽象基类"""

    @abstractmethod
    def chat(self, model, system, messages, tools=None, max_tokens=8000):
        """
        统一接口。返回统一格式的响应对象。
        """
        pass


class AnthropicClient(LLMClient):
    """Anthropic API 客户端（当前项目已有）"""

    def __init__(self):
        from anthropic import Anthropic
        self.client = Anthropic(base_url=os.getenv("ANTHROPIC_BASE_URL"))

    def chat(self, model, system, messages, tools=None, max_tokens=8000):
        kwargs = dict(model=model, system=system, messages=messages, max_tokens=max_tokens)
        if tools:
            kwargs["tools"] = tools
        resp = self.client.messages.create(**kwargs)
        return UnifiedResponse.from_anthropic(resp)


class OpenAIClient(LLMClient):
    """OpenAI 兼容 API 客户端（DeepSeek/Qwen/GPT 等）"""

    def __init__(self):
        from openai import OpenAI
        self.client = OpenAI(
            base_url=os.getenv("OPENAI_BASE_URL", "https://api.openai.com/v1"),
            api_key=os.getenv("OPENAI_API_KEY"),
        )

    def chat(self, model, system, messages, tools=None, max_tokens=8000):
        # 转换 system 格式
        oai_messages = []
        if isinstance(system, str):
            oai_messages.append({"role": "system", "content": system})
        elif isinstance(system, list):
            # 合并所有 text block（忽略 cache_control）
            sys_text = "\n".join(b["text"] for b in system if b.get("type") == "text")
            oai_messages.append({"role": "system", "content": sys_text})

        # 转换 messages 格式
        for msg in messages:
            oai_messages.append(self._convert_message(msg))

        # 转换 tools 格式
        oai_tools = None
        if tools:
            oai_tools = [self._convert_tool(t) for t in tools]

        resp = self.client.chat.completions.create(
            model=model,
            messages=oai_messages,
            tools=oai_tools,
            max_tokens=max_tokens,
        )
        return UnifiedResponse.from_openai(resp)

    def _convert_tool(self, tool):
        """Anthropic tool 格式 → OpenAI tool 格式"""
        return {
            "type": "function",
            "function": {
                "name": tool["name"],
                "description": tool.get("description", ""),
                "parameters": tool.get("input_schema", {}),
            }
        }

    def _convert_message(self, msg):
        """转换消息格式（处理 tool_use 和 tool_result）"""
        # ...省略，需要处理多种 content block 类型
        pass

        self.stop_reason = stop_reason
        self.usage = usage

    @classmethod

        return cls(
            content=resp.content,
            stop_reason=resp.stop_reason,
            usage=resp.usage,
        )

    @classmethod
    def from_openai(cls, resp):

        # ...需要转换 tool_calls → tool_use blocks
```

**优点**：
- 完全可控
- 不依赖第三方库
- 可以精细处理格式差异

**缺点**：
- 需要写 ~150 行适配代码
- 需要处理大量边界情况（消息格式转换、tool result 格式等）
- 每新增一个 API 格式需要维护
- 容易出 bug（格式转换是细节地狱）

### 9.2 方案 B：使用 litellm 库（推荐，如果不用 OpenRouter）

[litellm](https://github.com/BerriAI/litellm) 是一个专门做 LLM API 统一调用的库，支持 100+ 模型：

```python

response = completion(

        {"role": "system", "content": "You are a coding assistant."},
```

litellm 自动处理：

- 认证方式差异

**但 litellm 的输出是 OpenAI 格式**，而当前项目期望 Anthropic 格式的响应。所以需要做一层薄包装：

```python
# 用 litellm 但返回 Anthropic 兼容格式
import litellm

def llm_call(model, system, messages, tools=None, max_tokens=8000):
    """用 litellm 调用任意模型，返回 Anthropic 兼容格式"""

    # 如果是 Anthropic 模型，直接用原生 SDK（保留 cache_control 等特性）
    if model.startswith("claude") or model.startswith("anthropic/"):
        return native_anthropic_call(model, system, messages, tools, max_tokens)

    # 其他模型走 litellm
    oai_messages = convert_system_to_message(system, messages)
    oai_tools = convert_tools_to_openai(tools) if tools else None

    resp = litellm.completion(
        model=model,
        messages=oai_messages,
        tools=oai_tools,
        max_tokens=max_tokens,
    )

    return convert_response_to_anthropic(resp)
```

**优点**：
- 只需 `pip install litellm`
- 支持 100+ 模型，开箱即用
- 社区活跃，持续更新
- 内置重试、fallback、速率限制等功能

**缺点**：
- 额外依赖
- 仍需编写格式转换层（litellm 输出是 OpenAI 格式）
- 对 Anthropic 特有功能（cache_control）的支持可能不完整

## 12. 风险与注意事项

### 12.1 切换模型的常见坑

**坑 1：MODEL_CONTEXT_WINDOW 未调整**

这是最常见的问题。当前项目默认 `MODEL_CONTEXT_WINDOW=200000`（Claude 的窗口大小）。如果切换到 DeepSeek V3（64K 窗口）但忘记修改这个值：

```
有效窗口 = 200000 - 20000 = 180000
AutoCompact 阈值 = 180000 * 0.85 = 153000

但 DeepSeek V3 的实际窗口只有 64000！
→ 远在触发压缩之前，请求就会因超长而失败
```

**解决方案**：在 .env 中始终同时修改 MODEL_CONTEXT_WINDOW：

```bash
MODEL_ID=deepseek/deepseek-chat
MODEL_CONTEXT_WINDOW=64000      # 必须改！
```

**坑 2：API Key 环境变量名称**

当前项目读取的是 `ANTHROPIC_API_KEY`（Anthropic SDK 自动读取）。使用 OpenRouter 时，需要将 OpenRouter 的 Key 设为 `ANTHROPIC_API_KEY`：

```bash
# 正确
ANTHROPIC_API_KEY=sk-or-v1-xxxxx

# 错误（SDK 读不到）
OPENROUTER_API_KEY=sk-or-v1-xxxxx
```

**坑 3：ANTHROPIC_AUTH_TOKEN 冲突**

代码中有这段逻辑：

```python
if os.getenv("ANTHROPIC_BASE_URL"):
    os.environ.pop("ANTHROPIC_AUTH_TOKEN", None)
```

这意味着设置了 `ANTHROPIC_BASE_URL` 后，`ANTHROPIC_AUTH_TOKEN` 会被清除。如果你的认证依赖 AUTH_TOKEN 而不是 API_KEY，可能会出问题。

**坑 4：模型 ID 格式差异**

不同平台的模型 ID 不同：

| 平台 | DeepSeek V3 的模型 ID |
|------|---------------------|
| OpenRouter | `deepseek/deepseek-chat` |
| DeepSeek 官方 | `deepseek-chat` |
| SiliconFlow | `deepseek-ai/DeepSeek-V3` |
| litellm | `deepseek/deepseek-chat` |

**坑 5：工具数量限制**

某些模型对工具数量有限制：

| 模型 | 最大工具数 |
|------|------:|
| Claude | 128 |
| GPT-4o | 128 |
| DeepSeek V3 | 64 |
| Qwen 2.5 | 64 |

当前项目注册了约 10+ 工具，不会触及限制。但如果后续增加更多工具或使用 MCP 扩展工具集，需要注意。

### 12.2 安全注意事项

1. **API Key 安全**：不要将 API Key 提交到 Git。确保 `.env` 在 `.gitignore` 中。
2. **代理服务可信度**：使用第三方代理时，你的所有对话内容都会经过代理服务器。选择可信的服务（如 OpenRouter、SiliconFlow）。
3. **成本控制**：设置用量限额，防止意外超支。OpenRouter 和大多数 API 平台都支持设置月度限额。

### 12.3 回退策略

如果新模型出现问题，随时可以切回 Claude：


## 附录 E：OpenRouter + Qwen3.6 Plus 免费模型接入实战

### E.1 OpenRouter 支持 Anthropic SDK 吗？

**不支持。OpenRouter 只支持 OpenAI SDK 格式。**

| API 端点 | 格式 | OpenRouter 支持？ |
|---------|------|-----------------|
| `/v1/chat/completions` | OpenAI 格式 | ✅ 支持 |
| `/v1/messages` | Anthropic 格式 | ❌ **不支持** |

当前项目使用 `from anthropic import Anthropic`，SDK 内部请求的是 `{base_url}/v1/messages`。OpenRouter 不识别这个端点，会返回 404。

**所以：不能简单改 `base_url` 就切换到 OpenRouter。**

之前文档中说"OpenRouter 兼容 Anthropic 格式"是**不准确的**，此处修正。OpenRouter 官方文档只提供了 OpenAI SDK 的示例，没有 Anthropic SDK 的示例，正是因为他们不支持 Anthropic 格式。

### E.2 解决方案：用 OpenAI SDK 替代（最小改动）

**方案：安装 `openai` 包，在项目中添加一个 OpenAI 兼容客户端。**

核心思路：OpenRouter 兼容 OpenAI API 格式，所以用 `openai` SDK 连接 OpenRouter，调用 Qwen 模型。

#### 步骤 1：安装 openai 包

```bash
pip install openai
```

#### 步骤 2：创建 `.env` 配置

```bash
# .env
LLM_PROVIDER=openai              # 新增：选择 provider
OPENAI_BASE_URL=https://openrouter.ai/api/v1
OPENAI_API_KEY=sk-or-v1-你的key
MODEL_ID=qwen/qwen3.6-plus:free
```

#### 步骤 3：修改 `bootstrap/state.py`（~15 行改动）

```python
# bootstrap/state.py — 多 Provider 支持

if LLM_PROVIDER == "openai":
    from openai import OpenAI
    client = OpenAI(
        base_url=os.getenv("OPENAI_BASE_URL"),
        api_key=os.getenv("OPENAI_API_KEY"),
    )

    from anthropic import Anthropic
    client = Anthropic(base_url=os.getenv("ANTHROPIC_BASE_URL"))

MODEL = os.environ["MODEL_ID"]
```

#### 步骤 4：修改 `query.py` 中的 API 调用（~30 行改动）

Anthropic SDK 和 OpenAI SDK 的调用方式不同：

```python
# Anthropic 格式（当前）
response = client.messages.create(
    model=MODEL,
    system=system_prompt,    # 独立参数
    messages=messages,
    tools=tool_defs,
    max_tokens=8000,
)
# response.content[0].text / response.stop_reason / response.usage.input_tokens

# OpenAI 格式（OpenRouter/Qwen）
response = client.chat.completions.create(
    model=MODEL,
    messages=[{"role": "system", "content": system_text}] + messages,  # system 在 messages 里
    tools=[_convert_tool(t) for t in tool_defs],  # input_schema → parameters
    max_tokens=8000,
)
# response.choices[0].message.content / response.choices[0].finish_reason / response.usage.prompt_tokens
```

**关键差异需要适配**：

| 差异 | Anthropic | OpenAI |
|------|-----------|--------|
| system prompt | `system=` 独立参数 | `messages[0]={"role":"system"}` |
| 工具 schema 字段 | `input_schema` | `parameters` |
| 工具调用返回 | `content` 中的 `tool_use` block | `tool_calls` 字段 |
| 停止原因 | `stop_reason = "tool_use"` | `finish_reason = "tool_calls"` |
| token 统计 | `usage.input_tokens` | `usage.prompt_tokens` |
| cache_control | 支持 | 忽略（不报错） |

#### 步骤 5：抽取适配层（推荐，~80 行）

为了不让 query.py 充满 if/else，建议抽取一个适配层：

```python
# services/llm_adapter.py

class LLMAdapter:
    """统一的 LLM 调用接口，屏蔽 Anthropic/OpenAI 格式差异。"""
    
    def __init__(self, provider, client, model):
        self.provider = provider
        self.client = client
        self.model = model
    
    def chat(self, system_prompt, messages, tools, max_tokens=8000):
        """统一调用，返回标准化的 Response 对象。"""
        if self.provider == "anthropic":
            return self._call_anthropic(system_prompt, messages, tools, max_tokens)
        else:
            return self._call_openai(system_prompt, messages, tools, max_tokens)
    
    def _call_anthropic(self, system_prompt, messages, tools, max_tokens):
        resp = self.client.messages.create(
            model=self.model, system=system_prompt,
            messages=messages, tools=tools, max_tokens=max_tokens,
        )
        return StandardResponse(
            content=resp.content,
            stop_reason=resp.stop_reason,
            input_tokens=resp.usage.input_tokens,
            output_tokens=resp.usage.output_tokens,
        )
    
    def _call_openai(self, system_prompt, messages, tools, max_tokens):
        # 转换 system prompt
        sys_text = system_prompt if isinstance(system_prompt, str) \
            else "\n\n".join(b["text"] for b in system_prompt)
        oai_messages = [{"role": "system", "content": sys_text}] + messages
        
        # 转换工具定义
        oai_tools = [self._convert_tool(t) for t in tools] if tools else None
        
        resp = self.client.chat.completions.create(
            model=self.model, messages=oai_messages,
            tools=oai_tools, max_tokens=max_tokens,
        )
        
        # 标准化响应（转为 Anthropic 风格的 content blocks）
        choice = resp.choices[0]
        content = self._convert_response(choice)
        stop = "tool_use" if choice.finish_reason == "tool_calls" else "end_turn"
        
        return StandardResponse(
            content=content,
            stop_reason=stop,
            input_tokens=resp.usage.prompt_tokens,
            output_tokens=resp.usage.completion_tokens,
        )
```

这样 `query.py` 只需改一行：
```python
# 从 client.messages.create(...) 改为
response = state.llm.chat(system_prompt, messages, tool_defs)
```

### E.3 工作量估算

| 方案 | 改动量 | 复杂度 | 说明 |
|------|--------|--------|------|
| **方案 A：直接 if/else** | ~50 行 | 低 | 在 query.py/subagent.py 中分支 |
| **方案 B：LLMAdapter 适配层** | ~120 行 | 中 | 抽象干净，后续加模型零成本 |

**推荐方案 B**——一次投入 120 行，以后加任何新模型只需改 `.env`。

### E.4 使用 Qwen3.6 Plus 的注意事项

| 注意事项 | 说明 |
|---------|------|
| **Tool Calling** | Qwen3.6 支持 Function Calling，但质量可能不如 Claude/GPT |
| **免费限制** | OpenRouter 免费模型有速率限制（通常 10-20 RPM） |
| **上下文窗口** | 需要设置 `MODEL_CONTEXT_WINDOW` 环境变量匹配 Qwen 的窗口大小 |
| **Prompt Cache** | 不支持（`cache_control` 字段会被忽略，不影响功能） |
| **响应格式** | tool_use 的参数格式可能略有差异，需要测试 |
