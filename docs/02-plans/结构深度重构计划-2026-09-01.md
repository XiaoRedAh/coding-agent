## 三、目标架构

### 3.1 分层配置系统（核心新增，直接回应"配置外置"需求）

```
优先级（低 → 高）：
config/defaults.yaml          # 内置默认值（随项目分发，全量参数 + 注释）
  < ~/.xiaoagent/config.yaml  # 用户全局覆盖
  < {workdir}/.xiaoagent/config.yaml  # 项目级覆盖
  < .env                      # 仅机密（API key）+ 模型选择
  < 环境变量                   # 单值临时覆盖（CI 场景）
```

- `config/loader.py`：分层合并 → 校验（类型/范围，错配即报清晰错误）→ 生成**冻结 dataclass**：
  `Settings(llm, loop, compact, retry, mcp, shell, memory, paths, tools)` 一次构建，全程序只读。
- 原则：**代码里不出现任何裸数字**（除纯算法内部量）；所有可调参数进 `defaults.yaml` 且带注释。
- `.env` 只留机密与模型标识（key、base_url、model_id），行为参数全部进 yaml。
- Agent 类型定义（提示词/工具集/max_turns/是否后台）也改为 YAML 加载，**内置类型与用户自定义类型同构**（放 `.xiaoagent/agents/*.yaml` 即成为新的子 agent 类型，AgentTool 的 enum 动态生成）——这一并解决 B3。

### 3.2 目标目录结构

```
coding-agent/
├── main.py                     # 入口：装配 Settings → Runtime → REPL
├── config/
│   ├── defaults.yaml           # 全量默认配置（带注释）
│   └── loader.py               # 分层加载 + 校验
├── core/
│   ├── runtime.py              # 依赖容器（显式注入，替代 bootstrap/state 全局单例）
│   ├── loop.py                 # ★ 统一 Agent Loop（主/子 agent 共用一套实现）
│   ├── events.py               # 统一通知总线（bg 任务 + agent 任务合并）
│   └── logging.py              # 结构化日志（替代 print）
├── llm/
│   ├── adapter.py              # Anthropic/OpenAI 双格式（现 services/llm.py）
│   ├── errors.py               # 错误分类/重试（现 api_errors.py）
│   └── json_repair.py          # 截断 JSON 修复
├── context/
│   ├── prompt_builder.py       # system prompt 动静分离
│   └── compact.py              # 5 级压缩（阈值全部来自 Settings）
├── agents/
│   ├── builtins/               # 内置 agent 定义（YAML）
│   ├── registry.py             # 内置+自定义统一注册表
│   ├── subagent.py             # 派生执行（薄封装，调 core/loop）
│   └── coordinator.py          # Orchestrator 模式
├── tools/                      # 各工具（配置注入；grep 改纯 Python 实现）
├── workflows/                  # SOP 引擎（结构保持，配置外接）
├── services/                   # memory / mcp / permissions / tasks
├── ui/
│   ├── repl.py                 # 交互循环
│   └── render.py               # 全部终端渲染（spinner/权限确认/状态行）
└── tests/                      # 结构随源码镜像
```

### 3.3 关键设计决策

1. **统一 Loop（解决 A3）**：`core/loop.py` 提供 `AgentLoop`，主 agent 与子 agent 只是**不同配置**（system prompt、工具集、max_turns、是否流式、权限模式）而非两套代码。主循环特有的权限确认/截断恢复做成可插拔 hook。
2. **Runtime 容器（解决 A1/A2）**：`Runtime(settings, llm, tools, agents, ...)` 显式传递，`WORKDIR` 变为 `runtime.paths.workdir`。工具签名从 `handle(file_path)` 变为绑定 runtime 的闭包/方法。模块 import **零副作用**（不读 .env、不绑 cwd）。
3. **UI 与逻辑分离（解决 A6/B6）**：core 层只发事件/调回调（`on_text`, `on_tool_start`, `on_permission_request`），`ui/render.py` 实现终端渲染。日志走 `core/logging.py`，print 只存在于 ui 层。
4. **结构化工具结果（解决 B5）**：`ToolResult(ok: bool, content: str, error: str | None)`，替代字符串前缀嗅探。
5. **grep 纯 Python 化（解决 B4）**：用 `re` 遍历文件实现，跨平台、可测、行为可控（编码显式 UTF-8，顺带解决 C1 同类问题）。
6. **单条后台路径（解决 B2）**：BashTool 的 run_in_background 与 BackgroundManager 合并为 core/events 驱动的单一实现。
